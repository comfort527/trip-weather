# 整理下一項

指定項目：$ARGUMENTS（空白代表第一個未打勾的項目）

## 鐵則
- 一次只做一個項目，不順手修改其他地方。
- 不可改變網站的外觀與功能；若必須改變，先問使用者。
- 所有回報使用繁體中文。

## 步驟

### 1. 讀取
讀取 `CLAUDE.md` 與 `REFACTOR_PLAN.md`。若 `REFACTOR_PLAN.md` 不存在，請使用者先執行 `/site-check`，然後停止。

### 2. 選擇項目
有指定編號就做該項，否則選第一個未打勾 `[ ]` 的項目。若它依賴的項目尚未完成，告訴使用者並建議先做哪一項。

### 3. 動手前說明
簡短說明：
- 要改哪些檔案
- 改完預期的結果
- 可能的風險

若項目風險為「高」，或包含搬移檔案、修改路徑、刪除大段程式碼，先列出所有受影響的地方，**等使用者確認後才動手**。

### 4. 修改
只處理這一項。若過程中發現新問題，記到 `REFACTOR_PLAN.md` 末尾成為新項目，不要現在處理。

### 5. 自我驗證
- 再次搜尋原本的問題，確認已經消失
- 確認所有被修改或新增的 `href`、`src`、`import` 路徑都指向存在的檔案
- 若改了 `<script>` 為 `type="module"`，確認沒有任何 inline 事件屬性還在呼叫全域函式
- 若有 `screenshots/baseline/` 且環境可執行 Playwright，重新截圖並比對差異

### 6. 更新計畫
在 `REFACTOR_PLAN.md` 把該項改成 `[x]`，加上完成日期與一行說明。

### 7. 回報
- 改了哪些檔案、做了什麼（條列）
- **請使用者手動驗證的項目**：列出 `TEST_CHECKLIST.md` 中相關的幾項，並提醒打開瀏覽器 Console 確認沒有紅字
- 建議的 commit 訊息（不要自動 commit）
- 提醒：「驗證沒問題、存檔（commit）後，再輸入 `/fix-next` 做下一項。」
