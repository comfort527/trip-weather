# 網站健康檢查

檢查範圍：$ARGUMENTS（空白代表整個專案）

## 鐵則
- 本流程只讀不改。除了 `TEST_CHECKLIST.md`、`REFACTOR_PLAN.md`，以及 CLAUDE.md 中空白的「專案資訊」欄位之外，不得修改任何檔案。
- 所有回報使用繁體中文。

## 步驟

### 1. 讀取規則
讀取專案根目錄的 `CLAUDE.md`。若不存在，停止並告訴使用者需要先建立 CLAUDE.md。

### 2. 盤點專案
列出所有 HTML、CSS、JS 檔案與各自的行數，找出每一頁引用了哪些 CSS 與 JS。
若 CLAUDE.md 的「專案資訊」仍是空白（＿＿＿＿），依網站實際內容填寫。

### 3. 建立或更新 `TEST_CHECKLIST.md`
列出每一頁與每個可操作的功能（按鈕、表單、選單、輪播、彈出視窗、API 載入的內容等），格式：

```
## 頁面名稱（檔案路徑）
- [ ] 功能：操作步驟 → 預期結果
```

檔案已存在時只補充缺漏的項目，不刪除既有項目。

### 4. 逐項檢查
對照 CLAUDE.md，檢查以下項目，每個問題都要記下檔案與行號：

**穩定與資安（最優先）**
- 空的 `catch {}`，或 catch 裡只有註解
- `fetch` 沒檢查 `response.ok`、沒有錯誤處理
- 把變數或 API 資料放進 `innerHTML`
- 讀取巢狀資料沒有用 `?.` / `??`，缺欄位會讓頁面壞掉
- 非同步內容缺少「載入中」、「錯誤」、「空資料」畫面
- 失效的連結與資源：`href`、`src` 指向不存在的檔案

**HTML**
- inline `style="..."`、inline `onclick` 等事件屬性
- 圖片缺 `alt`、表單欄位缺 `<label>`
- 一頁有多個 `<h1>` 或標題跳級
- 跨頁複製貼上的頁首、頁尾、導覽列

**CSS**
- `tokens.css` 以外寫死的色碼（`#xxx`、`rgb()`、`hsl()`）與重複出現的數值
- `!important`、用 `#id` 寫樣式、巢狀超過 3 層
- 重複或沒有被任何 HTML 使用的規則

**JavaScript**
- `var`、全域變數、沒用 ES Modules
- 超過 40 行的函式、超過 200 行的檔案
- if 巢狀超過 2 層
- 散落各處的狀態字串、多個布林旗標表示同一件事
- 沒有被呼叫的函式

**結構**
- 檔案位置與 CLAUDE.md 的目錄結構不符（只記錄，風險標為高）

### 5. 選用：自動檢查
若環境已安裝 Node.js，詢問使用者是否要用 Playwright 開啟每一頁，記錄 Console 錯誤，並在 375px 與 1280px 寬度截圖存到 `screenshots/baseline/`，作為之後比對的基準。使用者同意才執行。

### 6. 建立或更新 `REFACTOR_PLAN.md`
把問題整理成待辦清單，格式：

```
# 整理計畫
最後檢查日期：YYYY-MM-DD

- [ ] #1【風險：低】標題
  - 檔案：…
  - 問題：…
  - 做法：…
  - 驗證：…（對應 TEST_CHECKLIST 的哪幾項）
```

排序原則：
1. 穩定與資安 → 抽出 tokens.css → 刪除無用程式碼 → 共用頁首頁尾 → JS 拆檔與改成 module → 搬移目錄
2. 被其他項目依賴的排前面
3. 每一項要小到一次能做完（大約 5 個檔案以內），太大就拆成多項

檔案已存在時：保留已打勾 `[x]` 的項目，更新其餘項目，新問題接在後面編號。

### 7. 回報
用簡短的繁體中文回報：
- 一句話說明網站整體狀況
- 各類別的問題數量
- 最該先做的 3 項，以及原因
- 下一步：「確認計畫沒問題後，輸入 `/fix-next` 開始整理第 1 項。」
